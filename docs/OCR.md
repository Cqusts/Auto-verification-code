# 图片验证码识别

## 工作流程

```
找到验证码图片 → 取像素（不重新请求 URL）→ 预处理 → OCR → 按字符集/长度清洗 → 填入
```

**「不重新请求 URL」是关键。** 绝大多数验证码接口每被请求一次就换一张新图，如果扩展再去 GET 一次图片地址，用户眼前看到的那张就作废了。所以取像素按这个顺序尝试：

1. 把页面上**已经解码好**的 `<img>` / `<canvas>` 画到离屏 canvas 上读取 —— 零成本、完全准确；
2. 若图片跨域导致 canvas 被污染，则**截取当前标签页并按元素位置裁剪** —— 同样是「所见即所得」，不产生新请求；
3. 实在拿不到（元素在视口外且跨域）才回退到后台 `fetch`，并优先走浏览器缓存。

## 支持与不支持

**支持**：清晰或轻度干扰的数字 / 英文字母验证码，也就是国内网站最常见的那种四位字符图。

**不支持**：滑块拖动、点选文字、图片旋转、算术题、reCAPTCHA、hCaptcha 等交互式验证。这些不是 OCR 问题，扩展会直接忽略它们。

## 调参：从「识别测试」开始

**设置 → 图片验证码 → 识别测试**：拖入或 `Ctrl+V` 粘贴一张验证码图片，会并排显示原图与预处理后的图，以及识别结果、置信度和所用方案。

**先看预处理后的图。** 判断标准很简单：字符是否清晰、完整、黑底白字分明。预处理图看着都费劲，OCR 一定认不出来。

| 现象 | 调整 |
| --- | --- |
| 字符被腐蚀、断笔画 | 关闭「二值化」，或把「二值化阈值」从 0（自动）调到 100–160 试 |
| 背景噪点仍然很多 | 开启「去噪点」，提高「放大倍数」到 4 |
| 深色背景浅色字 | 保持「自动反色」开启（默认） |
| 图片带边框被识别成字符 | 「裁边像素」调到 2–4 |
| 结果多字符或少字符 | 设定准确的「期望长度」，扩展会据此挑选最佳候选 |
| 混淆 0/O、1/l、5/S | 把「字符集」收窄到实际用到的范围，例如纯数字 |
| 反复返回空结果 | 试「版面模式」8（单个词）或 13（原始单行） |

### 内部已经做了什么

每次识别会自动尝试多套方案并取最优（置信度 + 长度是否匹配）：

1. 二值化 + 去噪 + 放大，按你设定的版面模式
2. 反色版本（应对深底浅字）
3. 仅灰度不二值化，切换版面模式

一旦某个方案「长度正确且置信度足够高」就提前结束，不会浪费 CPU。识别结果还会按字符集白名单清洗、按期望长度截断。

置信度低于「最低置信度」时不会直接填入，而是在输入框旁给出结果和一个 **采用** 按钮，由你决定。

## 换图重试

识别不出来时，扩展会点击验证码图片触发换图并重试，次数受「换图重试次数」限制（上限 3 次，默认 2 次），另有每分钟最多 12 次识别的硬性频率限制，避免异常情况下打爆站点接口。

## 接入自建 OCR 服务

内置引擎认不出某类验证码时，可以换成本机运行的专用模型（如 [ddddocr](https://github.com/sml2h3/ddddocr)），它对国内验证码的准确率通常明显更高。

一个最小的 ddddocr HTTP 服务：

```python
# pip install ddddocr flask
import base64, ddddocr
from flask import Flask, request, jsonify

app = Flask(__name__)
ocr = ddddocr.DdddOcr(show_ad=False)

@app.post("/ocr")
def solve():
    image = request.get_json(force=True)["image"]
    return jsonify(result=ocr.classification(base64.b64decode(image)))

app.run(host="127.0.0.1", port=9898)
```

扩展设置 → **图片验证码**：

| 字段 | 值 |
| --- | --- |
| 识别引擎 | 自建 HTTP 接口 |
| 接口地址 | `http://127.0.0.1:9898/ocr` |
| 提交格式 | JSON + base64 |
| 字段名 | `image` |
| 结果 JSON 路径 | `result` |

另外两种提交格式：`multipart/form-data`（文件字段名即「字段名」）和原始二进制（请求体就是 PNG 字节）。若接口直接返回纯文本结果，「结果 JSON 路径」留空即可。

> 图片只会发往你在这里填写的地址。请填本机或你自己掌控的服务 —— 把验证码图片发给第三方打码平台，等于把正在登录的账号线索交出去。

## 关于内置引擎的体积

`extension/vendor/tesseract/` 约 6 MB：WASM 内核 3.8 MB + 英文模型 1.9 MB + JS 胶水 0.2 MB。Manifest V3 禁止远程加载代码，因此这些文件必须随扩展一起分发。

需要更新或添加语言：

```bash
node scripts/fetch-vendor.mjs --lang eng --lang chi_sim
```

（中文模型体积大得多，且验证码基本用不到汉字，一般不需要。）
