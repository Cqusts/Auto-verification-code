# 把短信送进浏览器

浏览器沙箱里没有任何 API 能读取手机短信 —— Chromium 的 WebOTP 只在 Android 版浏览器、且短信格式特殊时才有效，桌面端完全用不上。所以这个扩展的做法是：**你自己搭一条从手机到电脑的通路，扩展只负责最后一步的解析与填写。**

下面四种方式任选其一。

---

## 方案 A：本地桥接 + 手机短信转发（推荐）

延迟最低、最稳定，适合日常使用。

```
手机收到短信 → 转发 App 发 HTTP POST → 电脑上的 bridge/server.mjs → WebSocket → 扩展 → 填入网页
```

### 1. 启动桥接服务

```bash
npm run bridge
# 或指定端口与令牌
node bridge/server.mjs --port 8787 --token my-secret
```

不指定 `--token` 时会自动生成一个随机令牌并打印出来。终端会同时打印手机端要用的地址。

> 服务默认监听 `0.0.0.0`，手机才能通过局域网访问。**请务必保留令牌**；如果只在本机自测，可以加 `--host 127.0.0.1`。

### 2. 配置扩展

扩展设置 → **短信来源** → **WebSocket 推送**：

| 字段 | 值 |
| --- | --- |
| 地址 | `ws://127.0.0.1:8787/ws` |
| 令牌 | 桥接服务打印的令牌 |

点 **测试连接**，显示「连接成功」即可。

### 3. 配置手机转发

#### Android

用任意一款支持 Webhook 的短信转发 App（如「短信转发器 / SmsForwarder」、Tasker、MacroDroid）。以短信转发器为例：

- 新建「发送通道」→ 类型选 **Webhook**
- 请求方式：`POST`
- WebHook 地址：`http://<电脑局域网IP>:8787/sms?token=<你的令牌>`
- 请求头：`Content-Type: application/json`
- 请求体模板：

  ```json
  {"from":"[from]","text":"[msg]"}
  ```

  （不同 App 的占位符写法不同，`[msg]`、`{{content}}`、`%text` 等，按该 App 的文档替换。）

- 新建「转发规则」，匹配条件建议设为「短信内容包含 *验证码*」，避免把全部短信都发出去。

> 电脑的局域网 IP：Windows 用 `ipconfig`，macOS / Linux 用 `ifconfig` 或 `ip addr`。手机与电脑需在同一 Wi-Fi 下。

#### iOS

用系统自带的 **快捷指令 → 自动化**：

1. 新建个人自动化 → **信息** → 设定「信息包含：验证码」
2. 添加操作 **获取 URL 内容**
   - URL：`http://<电脑局域网IP>:8787/sms?token=<你的令牌>`
   - 方法：`POST`
   - 请求体：`JSON`，添加字段 `text`，值选择「快捷指令输入 / 信息内容」
3. 关闭「运行前询问」

### 4. 验证

不接手机也能先跑通全链路：

```bash
curl -X POST "http://127.0.0.1:8787/sms?token=你的令牌" \
     -H 'Content-Type: application/json' \
     -d '{"text":"【测试】您的验证码是 123456，5分钟内有效"}'
```

网页上的验证码输入框应立即被填上。

## 方案 B：HTTP 轮询任意接口

如果你已经有一个能返回短信的接口（自建服务、云函数、内网 API），不必用本仓库的桥接服务。

扩展设置 → **短信来源** → **HTTP 轮询**：

| 字段 | 说明 |
| --- | --- |
| 地址 | 你的接口地址 |
| 轮询间隔 | 建议 3–5 秒 |
| JSON 路径 | 短信数组/文本在响应里的位置，如 `data.messages`；留空则自动探测 |
| 请求头 | 需要鉴权时填写，如 `Authorization` / `Bearer xxx` |

扩展能自动识别下列响应形态，通常无需填 JSON 路径：

```jsonc
"您的验证码是 123456"                                  // 纯文本
{"text": "..."}                                       // 也支持 content / body / msg / message / sms
{"messages": [{"id": "1", "text": "...", "receivedAt": 1730000000}]}
[{"body": "..."}, {"body": "..."}]
{"code": "123456"}                                    // 已经解析好的验证码
```

带 `id` 的消息会按 id 去重；没有 `id` 时按「时间戳 + 内容」去重，所以重复轮询同一条短信不会被重复填写。

## 方案 C：剪贴板

如果手机与电脑之间已有剪贴板同步（Windows 的「手机连接 / Phone Link」、部分国产手机的多屏协同、KDE Connect 等），可以让扩展直接盯着剪贴板。

扩展设置 → **短信来源** → **剪贴板** → 启用，并点 **授予剪贴板权限**。

- 默认只在「页面上存在验证码输入框」时读取，减少不必要的剪贴板访问。
- 浏览器要求页面处于前台且已获得焦点，读取才会成功；若被拒绝，可以在页面上的状态标签或扩展弹窗里点 **读取剪贴板** 手动触发一次。

---

## 方案 D：手动粘贴（零配置）

点击扩展图标，把整条短信粘进输入框，点 **解析并填写**。扩展会自己从短信里找出验证码。适合偶尔用一次的场景。

---

## 验证码是怎么被解析出来的

扩展不是简单地「取第一串数字」，而是给每个候选打分：

- 紧邻「验证码 / 校验码 / 动态码 / code / OTP」等关键词的数字加分，越近分越高
- 6 位、4 位这类常见长度加分
- 紧跟单位的数字扣分（`5分钟`、`300元`）
- 被「订单 / 尾号 / 手机号」等标签直接引导的数字扣分
- 手机号、URL 里的数字直接排除

关键词列表可在 **设置 → 常规 → 识别关键词** 中修改。长度范围、纯数字还是含字母也可以在同一处调整。
