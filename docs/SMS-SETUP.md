# 把短信送进浏览器

浏览器沙箱里没有任何 API 能读取手机短信 —— Chromium 的 WebOTP 只在 Android 版浏览器、且短信格式特殊时才有效，桌面端完全用不上。所以这个扩展的做法是：**你自己搭一条从手机到电脑的通路，扩展只负责最后一步的解析与填写。**

下面四种方式任选其一。

---

## 方案 A：本地桥接 + 手机短信转发（推荐）

延迟最低、最稳定，适合日常使用。

```
iPhone / Android            你的电脑
┌──────────────┐      ┌──────────────────────────────────────┐
│ 收到验证码短信 │      │  bridge/server.mjs                    │
│      ↓        │ HTTP │        ↓                             │
│  转发 App /   │─────▶│   （本机 WebSocket）                  │
│   快捷指令     │ POST │        ↓                             │
└──────────────┘      │   Edge 扩展 → 填入网页                 │
                      └──────────────────────────────────────┘
```

**手机上不需要配置任何 WebSocket。** 手机只做一次普通的 HTTP POST；WebSocket 是电脑内部「桥接服务 ↔ 扩展」那一段，地址 `ws://127.0.0.1:8787/ws` 里的 `127.0.0.1` 指的是电脑自己，只出现在电脑上的扩展设置里。

### 1. 启动桥接服务

```bash
npm run bridge
# 或指定端口与令牌
node bridge/server.mjs --port 8787 --token my-secret
```

不指定 `--token` 时会自动生成一个随机令牌并打印出来。终端会同时打印手机端要用的地址。

> 服务默认监听 `0.0.0.0`，手机才能通过局域网访问。**请务必保留令牌**；如果只在本机自测，可以加 `--host 127.0.0.1`。

### 2. 配置扩展

扩展设置 → **短信来源** → **WebSocket 推送**：

| 字段 | 值 |
| --- | --- |
| 地址 | `ws://127.0.0.1:8787/ws` |
| 令牌 | 桥接服务打印的令牌 |

点 **测试连接**，显示「连接成功」即可。

### 3. 配置手机转发

#### Android

用任意一款支持 Webhook 的短信转发 App（如「短信转发器 / SmsForwarder」、Tasker、MacroDroid）。以短信转发器为例：

- 新建「发送通道」→ 类型选 **Webhook**
- 请求方式：`POST`
- WebHook 地址：`http://<电脑局域网IP>:8787/sms?token=<你的令牌>`
- 请求头：`Content-Type: application/json`
- 请求体模板：

  ```json
  {"from":"[from]","text":"[msg]"}
  ```

  （不同 App 的占位符写法不同，`[msg]`、`{{content}}`、`%text` 等，按该 App 的文档替换。）

- 新建「转发规则」，匹配条件建议设为「短信内容包含 *验证码*」，避免把全部短信都发出去。

> 电脑的局域网 IP：Windows 用 `ipconfig`，macOS / Linux 用 `ifconfig` 或 `ip addr`。手机与电脑需在同一 Wi-Fi 下。

#### iOS

用系统自带的**快捷指令**，不需要装任何第三方 App。

**准备**：确认桥接服务在电脑上运行、记下令牌，查到电脑的局域网 IP（Windows `ipconfig`，macOS `ifconfig | grep "inet "`），形如 `192.168.1.23`。手机和电脑连同一个 Wi-Fi。

打开**快捷指令 App → 底部「自动化」→ 右上角 `+`**：

1. 触发条件选 **「信息」**
2. 勾选 **「信息包含」**，填 `验证码`
   > 想同时覆盖英文短信，就再建一条一模一样的自动化，条件填 `code`。一条自动化只能有一个匹配词。
3. 选 **「立即运行」**，并关掉 **「运行后通知」** —— 否则每条验证码都会弹一次提示
4. 下一步 → **「新建空白自动化」** → 添加操作
5. 搜索并添加 **「获取 URL 内容」**
6. URL 填：

   ```
   http://192.168.1.23:8787/sms?token=你的令牌
   ```

7. 点开 **「显示更多」**，按这样填：

   | 字段 | 值 |
   | --- | --- |
   | 方法 | `POST` |
   | 请求体 | `JSON` |
   | 字段（点「添加新字段」→ 文本） | 键名 `text` |
   | 该字段的值 | 从变量里选 **「快捷指令输入」** |

第 7 步的最后一行是唯一容易卡住的地方：值那一栏要点一下，从弹出的变量列表里选变量，**不要手打文字**。「信息」自动化会把短信全文作为「快捷指令输入」传进来；如果你的 iOS 版本显示的是「信息」或「信息内容」，选它，效果一样。

##### iOS 上的几个坑

- **必须同一个 Wi-Fi。** 手机切到蜂窝网络就到不了电脑，短信会静默丢弃 —— 快捷指令不会报错给你。
- **电脑 IP 会变。** 路由器重启或 DHCP 租约到期后换了 IP，快捷指令就失效了。建议在路由器里给电脑绑定固定 IP。
- **Windows 防火墙。** 桥接服务第一次运行时的弹窗要勾选「专用网络」允许，否则手机连不上。当时点了取消的话，去「Windows 防火墙 → 允许应用通过防火墙」里给 Node.js 补上。
- **「信息」自动化本身不是 100% 可靠。** 低电量模式、专注模式、长时间锁屏都可能让它延迟几秒，偶尔不触发。这是 iOS 的限制，不是扩展或桥接的问题。如果你用的是 Mac，[方案 C（剪贴板）](#方案-c剪贴板)配合通用剪贴板往往更稳。

##### 确认通了

让手机收一条验证码短信，看电脑上桥接服务的终端输出：

```
[15:32:07] sms -> 1 client(s): 【某某】您的验证码是 123456，5分钟内有效
```

- 出现这一行且 `1 client(s)` —— 全通了。
- 出现这一行但 `0 client(s)` —— 手机这段通了，但扩展没连上桥接。去扩展设置点「测试连接」。
- 这一行压根不出现 —— 问题在手机或防火墙那一段。先用下面的 `curl` 确认桥接服务本身是好的，再回头查快捷指令。

### 4. 验证

不接手机也能先跑通全链路：

```bash
curl -X POST "http://127.0.0.1:8787/sms?token=你的令牌" \
     -H 'Content-Type: application/json' \
     -d '{"text":"【测试】您的验证码是 123456，5分钟内有效"}'
```

网页上的验证码输入框应立即被填上。

## 方案 B：HTTP 轮询任意接口

如果你已经有一个能返回短信的接口（自建服务、云函数、内网 API），不必用本仓库的桥接服务。

扩展设置 → **短信来源** → **HTTP 轮询**：

| 字段 | 说明 |
| --- | --- |
| 地址 | 你的接口地址 |
| 轮询间隔 | 建议 3–5 秒 |
| JSON 路径 | 短信数组/文本在响应里的位置，如 `data.messages`；留空则自动探测 |
| 请求头 | 需要鉴权时填写，如 `Authorization` / `Bearer xxx` |

扩展能自动识别下列响应形态，通常无需填 JSON 路径：

```jsonc
"您的验证码是 123456"                                  // 纯文本
{"text": "..."}                                       // 也支持 content / body / msg / message / sms
{"messages": [{"id": "1", "text": "...", "receivedAt": 1730000000}]}
[{"body": "..."}, {"body": "..."}]
{"code": "123456"}                                    // 已经解析好的验证码
```

带 `id` 的消息会按 id 去重；没有 `id` 时按「时间戳 + 内容」去重，所以重复轮询同一条短信不会被重复填写。

## 方案 C：剪贴板

如果手机与电脑之间已有剪贴板同步（Windows 的「手机连接 / Phone Link」、部分国产手机的多屏协同、KDE Connect 等），可以让扩展直接盯着剪贴板。

扩展设置 → **短信来源** → **剪贴板** → 启用，并点 **授予剪贴板权限**。

- 默认只在「页面上存在验证码输入框」时读取，减少不必要的剪贴板访问。
- 浏览器要求页面处于前台且已获得焦点，读取才会成功；若被拒绝，可以在页面上的状态标签或扩展弹窗里点 **读取剪贴板** 手动触发一次。

---

## 方案 D：手动粘贴（零配置）

点击扩展图标，把整条短信粘进输入框，点 **解析并填写**。扩展会自己从短信里找出验证码。适合偶尔用一次的场景。

---

## 验证码是怎么被解析出来的

扩展不是简单地「取第一串数字」，而是给每个候选打分：

- 紧邻「验证码 / 校验码 / 动态码 / code / OTP」等关键词的数字加分，越近分越高
- 6 位、4 位这类常见长度加分
- 紧跟单位的数字扣分（`5分钟`、`300元`）
- 被「订单 / 尾号 / 手机号」等标签直接引导的数字扣分
- 手机号、URL 里的数字直接排除

关键词列表可在 **设置 → 常规 → 识别关键词** 中修改。长度范围、纯数字还是含字母也可以在同一处调整。
